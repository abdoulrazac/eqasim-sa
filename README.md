# eqasim-sa

**English** | [Français](README-fr.md)

`eqasim-sa` plans, runs, and analyzes sensitivity analysis campaigns for a
synpp-driven eqasim pipeline. Its current vocabulary is Grid, discrete OAT,
canonical Morris, historical Sobol, and multi-scramble Sobol. It provides deterministic plans, per-run resumption,
indicators computed from Parquet artifacts, and local and SLURM backends.

All generated starters, including calibration, Grid, discrete OAT, and Sobol,
are demonstrations: they
validate configuration, execution, storage, and analysis plumbing but cannot
support inferential or decision claims. No canonical Morris starter is generated;
its scientific claims, uncertainty model, estimand, budget, convergence criteria,
and robustness checks must be study-specific. Historical `method: morris` remains
readable only as legacy demonstration provenance. The generated `03-sobol.yml`
also remains a historical demonstration: its single scramble and row bootstrap
are noninferential. Its plan bytes, schema, outputs, and behavior are unchanged.

The generated Grid and Sobol examples vary the scalar eqasim-france
`matching_age_scheme`; discrete OAT leaves this categorical factor fixed, and
`analysis_age_scheme` remains fixed so output distributions stay comparable.
Discrete OAT uses adjacent numeric levels and local normalized effects; it is not
canonical Morris. Canonical Morris is supported only for scientific screening,
not factor prioritization or factor fixing. Scientific canonical Morris targets
the conditional mean over simulator seeds. Its `stochastic` charter declares a
pilot or production replication allocation and common random numbers within each
trajectory. A pilot is an immutable, separate campaign: analysis publishes
`noise-floor.parquet` and `replication-allocation.json`, which recommends a new
production campaign/root. Production records that recommendation as provenance
and never mutates or extends the pilot plan.

Study-authored `method: multiscramble_sobol` is scientific only, requires an
independent uncertainty model and objective `fp` or `ff`, and uses at least four
explicit independent QMC scramble seeds. It is deliberately not generated by
`init`. The finite `parameters.seed` support is a declared nuisance factor, not a
controllable input and not a claim about unrestricted intrinsic stochastic noise.
Its indices remain diagnostic, but it is non-actionable and excluded from FP/FF
ranks and tolerance classification. Convergence tables report
evidence at declared sample sizes; they do not automatically declare stopping
criteria satisfied.

The package targets exactly Python 3.13 (`>=3.13,<3.14`). Windows 10+, macOS
13+, and Linux are supported natively, installed with `uv` and without
administrator rights (on Windows:
`powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`);
verification on Windows and macOS is pending, see
[Platform verification](docs/platform-verification.md). On Windows without long
paths, a real eqasim run needs an administrator to enable them once (eqasim's own
cache exceeds 260 characters). The `local` backend works on all three; the
`slurm` backend requires Linux. A campaign runs entirely on one machine; analysis
can be done on another one. See [Getting started](docs/getting-started.md) and
[Troubleshooting](docs/troubleshooting.md) (Windows path length, line endings).
The shell examples below are Bash; on Windows, run them from Git Bash.
From this directory:

```bash
uv sync --extra test --locked
uv run --locked eqasim-sa --help
```

## Initialize a study

From the root containing `eqasim-sa/`, `eqasim-france/`, and `eqasim-data/`:

```bash
ROOT="$(pwd -P)"
SA=(uv run --project "$ROOT/eqasim-sa" --locked eqasim-sa)

"${SA[@]}" init \
  --project-name mon-etude \
  --model-root "$ROOT/eqasim-france" \
  --data-path "$ROOT/eqasim-data"
cd "$ROOT/mon-etude"
```

`init` generates only a template project and `manifest.json`, which hashes the
data tree. It does not create a plan and does not run synpp, a campaign, or an
analysis.

## Standard workflow

```bash
# First produce the resource calibration observations.
"${SA[@]}" plan --meta-config configs/00-calibration.yml
"${SA[@]}" run --meta-config configs/00-calibration.yml

# Then prepare, check, estimate, run, and analyze a target.
"${SA[@]}" plan --meta-config configs/01-grid.yml
"${SA[@]}" check --meta-config configs/01-grid.yml
"${SA[@]}" estimate --meta-config configs/01-grid.yml
"${SA[@]}" run --meta-config configs/01-grid.yml
"${SA[@]}" analyze --meta-config configs/01-grid.yml
```

Calibration covers runtime, durable storage, and worker cache. It does not
calibrate eqasim's scientific parameters.

## Structured matching configurations

Grid can compare named ordered `matching_attributes` lists while preserving the
resolved list in run identity and execution. The model YAML must already contain
the active list-valued key; use a new campaign/root for the derived target. See
the [practical structured-configurations tutorial](docs/structured-configurations-tutorial.md).
